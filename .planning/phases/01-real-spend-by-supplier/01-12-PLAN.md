## Phase Goal

**As a** business owner, **I want to** sign in and upload my invoice XML files, **so that** I see exact spend by supplier and month.

This plan delivers "upload my invoice XML files": files picked in the browser are parsed there and kept only in that browser, through the storage interface built in Plan 01-19. The legitimacy checkpoint, the installs, the port, both adapters and the contract suite moved to Plan 01-19 on 2026-10-12 to keep each plan within its context budget.

<objective>
Ship the thinnest real path from "Subir XML" to IndexedDB and back after a reload: the pure `ingestFiles` pipeline with the Plan 01-04 parser (D-21, D-22), the client store and provider in the `(app)` layout opening the Plan 01-19 `IndexedDbInvoiceStore` (D-23, D-28), the data strip on `/`, and a Chromium test. Then prove the safety properties on the same path: a stored UUID is never duplicated (ING-04, D-26), no invoice data reaches the server (D-22), a failed save stores nothing and says so, and a browser without IndexedDB gets an error instead of a memory fallback (D-33).

Purpose: success criteria 2 (upload, no duplicate) and 5 (stored only in this browser, survives reload, nothing reaches the server).
Output: ingest pipeline, client store, import session, provider, data strip, screen switch, the updated layout and page, and the e2e upload spec.
</objective>
