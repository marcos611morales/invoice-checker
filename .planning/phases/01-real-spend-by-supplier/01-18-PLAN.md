## Phase Goal

**As a** business owner, **I want to** sign in and upload my invoice XML files, **so that** I see exact spend by supplier and month.

This plan finishes the "sign in" half that Plan 01-11 started: the 01-UI-SPEC shell every later screen lives in, the sliding-session keep-alive, the server-side backstop for the browser wipe, and the structural test that keeps every entry point behind the allowlist. It was split out of Plan 01-11 on 2026-10-12 (former Task 3) to keep each plan within its context budget.

<objective>
Restyle the signed-in shell to 01-UI-SPEC and prove the sign-out path end to end through it: "Cerrar sesión" posts to the wrapped Better Auth route, which adds `Clear-Site-Data: "storage"` to the sign-out response (D-24 layer 3) and keeps every Set-Cookie. Then mount `SessionKeepAlive` so the 30-day session slides with use (D-18), and lock the "every entry point calls the DAL, no server functions, one route handler" rule (D-19) with a structural test.

Purpose: success criteria 1 (sessions persist, logout works, access denied on every page and route) and 5 (signing out removes browser data: the server backstop).
Output: the restyled `(app)` layout, `SessionKeepAlive`, the auth route wrapper, the `auth-route` and `entrypoints-guarded` unit tests, and two extended Playwright specs.

Sequencing note: the `01-04` entry in `depends_on` is an ordering edge only. Both plans share one working tree, and `pnpm typecheck` reads `.next/types` (tsconfig `include`) while this plan runs `pnpm build`, so the two must not run at the same time.
</objective>
