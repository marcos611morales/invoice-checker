## Spacing Scale

Declared values (multiples of 4). Tailwind step in parentheses.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (`1`) | Gap between a name and its RFC line; icon-to-label gaps |
| sm | 8px (`2`) | Compact gaps inside a control cluster; cell vertical padding adds to this; dialog footer button gap |
| md | 16px (`4`) | Default card padding and in-card block gap (shadcn `--card-spacing`); form field gaps; alert dialog padding; drag overlay inset |
| lg | 24px (`6`) | Gap between cards (`space-y-6`); header horizontal padding |
| xl | 32px (`8`) | Main content vertical padding (`py-8`) |
| 2xl | 48px (`12`) | Empty-state / access-denied / unavailable vertical padding |
| 3xl | 64px (`16`) | Not used in Phase 1 |

Layout rules:
- App shell: header height 56px (`h-14`), `border-b`. Header and `<main>` content share one container: `mx-auto w-full max-w-6xl px-6` (1152px max). `<main>` adds `py-8`.
- Everything is a single column of full-width cards at every breakpoint. No side-by-side charts in Phase 1.
- Under 640px: header wraps (brand row, then email and sign-out row), the email is hidden under 768px, tables and the top-10 chart scroll horizontally inside their card, the data-strip buttons wrap under its caption.

Exceptions:
- 12px (`gap-3`) is the **only** non-standard spacing value. It is allowed for header control clusters (email + sign-out), as it already is in `src/app/(app)/layout.tsx`. No other off-scale gap, padding or margin is permitted.
- Control heights follow the shadcn nova preset (`h-8` default, `h-9` for `lg`). This is a desktop-first internal tool, so the 44px mobile touch target is not enforced. Compensation: table rows keep at least 40px height (`py-2` on cells) and the primary button of each screen uses `size="lg"`.
- Chart heights are fixed content boxes, not spacing tokens: monthly chart `h-[280px]`, top-10 chart `h-[400px]`.
- The drag overlay border is a 2px dashed stroke (a border width, not a spacing token).

## Typography

Four sizes, two weights. Money, counts, percentages and the import counter always carry `tabular-nums`.

| Role | Size | Weight | Line Height | Used for |
|------|------|--------|-------------|----------|
| Caption | 12px (`text-xs`) | 400 | 1.5 (`leading-normal`) | RFC under a supplier name, data-strip caption, help text, summary count labels, chart tick labels, badges |
| Body | 14px (`text-sm`) | 400 | 1.5 (`leading-normal`) | Table cells, alerts, descriptions, problem list items, dialog description; also **card titles and the delete dialog title at weight 600** (`CardTitle` gets `className="text-sm font-semibold"`; `AlertDialogTitle` gets the same; the shipped 16px/500 defaults are overridden) |
| Heading | 20px (`text-xl`) | 600 | 1.2 (`leading-[1.2]`) | Page `h1` ("Gasto por proveedor", the supplier name), the empty-state card title, the three summary counts |
| Display | 30px (`text-3xl`) | 600 | 1.2 (`leading-[1.2]`) | The hero total ("$217,880.82"), the supplier-detail stat figures, the login and "Acceso denegado" `h1` (already built) |

Weights: **400** (regular) and **600** (semibold, `font-semibold`) only in authored markup. Exception: the generated shadcn primitives (`Button`, `Badge`, `Label`, `TableHead`) ship at 500 internally; this is accepted and must not be copied into authored class lists.

Rules:
- Muted text uses `text-muted-foreground`. Never place 12px muted text on a `muted` (grey) surface (contrast 4.4:1); put it on white / card only. The `AlertDialogFooter` ships with `bg-muted/50`: it holds only buttons, no Caption text.
- Supplier names and uploaded file names are untrusted text: rendered as plain React text, exactly as received (names are usually uppercase SAT `Nombre`). No `uppercase`/`capitalize` transforms.
- Money in tables is right-aligned; text columns left-aligned.

## Color

The existing theme is pure neutral greyscale from the nova preset. It stays; Phase 1 adds exactly one hue, teal (`--chart-1`), reserved for data.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` / `--card` `oklch(1 0 0)` (#FFFFFF) | Page background, every card, the table body |
| Secondary (30%) | `--muted` / `--secondary` `oklch(0.97 0 0)` (#F5F5F5) + `--border` `oklch(0.922 0 0)` (#E5E5E5) + text `--foreground` `oklch(0.145 0 0)` (#0A0A0A) and `--muted-foreground` `oklch(0.556 0 0)` (#737373) | Table header row, row hover (`bg-muted/50`), secondary badge, progress track, card ring, dividers, dialog footer, drag-overlay dashed border (`--muted-foreground`), text |
| Accent (10%) | `--chart-1` `oklch(0.52 0.10 215)` (about #0E7490); hover `--chart-2` | See reserved list below |
| Destructive | `--destructive` `oklch(0.577 0.245 27.325)` (about #E7000B) | Failure alerts and the delete-confirmation button only |

Primary buttons ("Seleccionar archivos XML", "Iniciar sesión con Google") use the preset `--primary` (near-black `oklch(0.205 0 0)`), not the teal accent. The progress fill also stays `bg-primary`.

Accent reserved for (and nothing else):
1. Bar fill in the three charts (monthly spend, top-10 suppliers, supplier-detail monthly spend); hovered bar uses `--chart-2`.

(The 2px active-nav indicator of the Drive version is gone: Phase 1 has no nav links, see Shell.)

Destructive reserved for: `Alert variant="destructive"` (IndexedDB unavailable, unreadable stored records, import could not be saved, delete failed) and the `AlertDialogAction variant="destructive"` "Borrar facturas" in the confirmation dialog. The "Borrar facturas" trigger in the data strip is a neutral `ghost` button; only the final confirmation is red. Negative amounts are **not** red: they show the minus sign from `Intl` and the same foreground color, because an Egreso netting a month below zero is a normal business fact, not an error.

Non-color cues: every state conveyed by color is also conveyed by text or icon (alerts carry an icon and a title; "Contado" / "No contado" are words; the drag overlay carries text and an icon, not just a border).

Chart styling (all three charts): horizontal grid lines only, `stroke` `var(--border)`; axis lines hidden; tick text 12px `var(--muted-foreground)`; bar corner radius 4px on the free end; `isAnimationActive={false}` (static dashboard, also honors reduced motion); no legend (single series); a zero baseline (`ReferenceLine y={0}` / `x={0}`) in `var(--border)`.

## Screens and Layout

Every screen below renders from one of four browser-store snapshot states (RESEARCH Pattern 4): `loading`, `unavailable`, `ready` with zero invoices, `ready` with invoices. The server renders only the shell; nothing in this section needs invoice data on the server.

### Shell (`src/app/(app)/layout.tsx`)
Left: brand text "Facturas — Análisis de gastos" (Body, 600; shows only "Facturas" under 640px) as a link to `/`. **No nav links in Phase 1**: the Drive version had "Resumen" and "Ajustes", but Ajustes no longer exists and a one-item nav adds nothing; the brand link is the way home and Phase 2 can add nav when a second destination exists. Right: the signed-in email (Body, muted, hidden under 768px) and the existing outline "Cerrar sesión" button. `<SessionKeepAlive />` renders nothing. The shell also mounts the browser-store provider and the window-level **drag overlay** (below), so a drop works on any `(app)` page.

**Where things live (placement decision).** There is no Ajustes page. Upload lives in the **data strip** on `/` (and in the empty state, which replaces the dashboard when nothing is stored). Delete lives only in the data strip. Reason: both actions operate on the same thing (the invoices in this browser), the strip is always visible at the top of the only screen that shows them, and a settings page with one destructive button would be a page to maintain for nothing.

### Dashboard `/` — invoices present (`ready` with a non-null DTO), top to bottom
1. **Page header** (flex, wraps, `gap-4`): `h1` "Gasto por proveedor" (Heading); right side, `YearSelect` (inline `Label` "Año" 14px + `Select` 120px wide) and `Badge variant="secondary"` "Montos con IVA (Total del XML)".
2. **Unreadable-records alert** (only when the store reports `invalidRecords > 0`): `Alert variant="destructive"` with `TriangleAlert`, see Copywriting.

Row (`flex flex-wrap items-center justify-between gap-4`): left, Caption muted "Facturas guardadas solo en este navegador: {n}. Se borran al cerrar sesión." (n with `tabular-nums`, es-MX separators; n counts every stored XML: Ingreso, Egreso and Pago). Right, a cluster `gap-2`: `Button variant="outline"` "Subir XML" with a leading `Upload` icon, and `Button variant="ghost"` "Borrar facturas" with a leading `Trash2` icon (opens the delete dialog). When an import is running or has finished, the **import panel** expands inside this same card under a `Separator` (see States).

A drop while an import is running, while a dialog is open or while `unavailable` is ignored (default prevented, no overlay).

## States and Interactions

**YearSelect**: a change updates `?anio=` with `window.history.replaceState` (shallow routing, no server round trip) and recomputes in memory, so there is **no pending state**: no `useTransition`, no disabled select, no `aria-busy`, no `opacity-60`. Years are listed newest first. One year still renders the control. Uploading older years does not change the selected year.

### Upload control and import panel

Entry points: `Button` "Subir XML" (data strip), `Button` "Seleccionar archivos XML" (empty state), and dropping files anywhere on a page. The buttons open a hidden native `<input type="file" multiple accept=".xml,application/xml,text/xml">` (the input is `hidden` and `tabIndex={-1}`; the button is the single tab stop). Filtering is by file name (`.xml`, case-insensitive), never by MIME type. Cancelling the picker (empty selection) does nothing: no panel, no state change. The input value is reset after each selection so choosing the same files again works.

Pre-checks before any file is read:
1. **More than 1,000 files selected or dropped (D-35)**: nothing is imported. The import panel shows an `Alert` (default variant, `Info` icon) with the limit copy and a `Button variant="ghost" size="sm"` "Entendido" that dismisses it. The count includes non-XML files.
2. Otherwise the import starts: non-`.xml` names and dropped folders become listed problems without being read; a file over 2,000,000 bytes (Plan 01-04 `MAX_XML_BYTES`) becomes a listed problem without being read.

| State | UI |
|-------|----|
| Idle, nothing stored | Guided empty state. |
| Idle, invoices stored | Data strip caption; buttons "Subir XML" and "Borrar facturas" enabled. |
| Running | "Subir XML" / "Seleccionar archivos XML" disabled, label "Importando…", spinning `LoaderCircle`; "Borrar facturas" disabled. Under a `Separator`: `Progress` (`h-2`, `aria-label="Progreso de la importación"`) at `done / total` and the line "Importando {done} de {total}…" (Body, `tabular-nums`, es-MX numbers; the visual counter is updated at most every 50-100 ms and has `aria-hidden`). A separate visually hidden `role="status"` `aria-live="polite"` node announces only "Importando {total} archivos." at the start and the final summary at the end (no per-file announcements). |
| Saving | When `done` reaches `total` and the single atomic save is in flight: the line reads "Guardando en este navegador…" (the bar stays at 100%). |
| Done | Summary block (below). |
| Done, nothing new and nothing wrong | Body line above the counts: "Todas las facturas ya estaban guardadas; no se agregó nada." |
| Save failed | `Alert variant="destructive"` with `CircleAlert` in the panel: title and body in Copywriting. Nothing from that import was stored. The buttons return to idle. |

**Summary block (D-25, D-36).** A `Separator` above, then:
- Header row: Body 600 "Resumen de la importación" on the left, `Button variant="ghost" size="sm"` "Cerrar resumen" on the right; under the title a Caption muted "{total} archivos revisados".
- Counts: a `<dl>` with three items in a row (`grid grid-cols-3 gap-4`; do not stack, the labels are short): each item has the number in Heading (20/600, `tabular-nums`) and the label under it in Caption muted: **"Nuevas"**, **"Ya guardadas"**, **"Con problemas"**. All three always show, including zeros.
- Counting contract (the planner implements it, the tests assert it): each file counts in exactly one of **Nuevas** (stored now, including invoices stored with a flag such as "total no cuadra"), **Ya guardadas** (UUID was already stored; the stored invoice is unchanged, D-26), or **not imported** (unreadable, wrong type, too large, repeated UUID in the same import, and so on). **Con problemas** = not imported + new invoices stored with a flag. So a flagged invoice that counts is in Nuevas **and** in Con problemas, and `Nuevas + Ya guardadas + not imported = {total}`. A file whose UUID was already stored is not listed as a problem even if it carries a flag; it counts only in Ya guardadas.
- When at least one listed problem counts (Contado), a Caption muted line under the counts: "Las facturas con aviso se cuentan en Nuevas y también en Con problemas."
- If there are problems: the `<details>` "Ver archivos con problemas ({n})". It is `open` by default when Nuevas and Ya guardadas are both 0, closed otherwise.

**Problem list** (`<details>`): summary row "Ver archivos con problemas ({n})" with a `ChevronRight` that rotates when open; the body is a list capped at `max-h-64 overflow-y-auto`; one row per file: "{fileName} — {mensaje}" (Body; `fileName` has `break-all`, stored/rendered at most 255 characters) plus a `Badge`: `outline` **"Contado"** when the invoice was stored (it is also in Nuevas), `secondary` **"No contado"** when it was not imported. The summary stays until the user presses "Cerrar resumen", starts another import (it is replaced) or signs out. It is not persisted: a reload clears it (an import interrupted by a reload stores nothing, and the user sees the previous state). There is no cancel button: the import is short (about 1 second per 1,000 files) and closing the tab is safe.

### Delete invoices (D-24)
"Borrar facturas" (data strip) opens an `AlertDialog`: title (Body 600), description, footer with `AlertDialogCancel` "Cancelar" (`outline`, receives initial focus, which is Radix's default) and `AlertDialogAction` `variant="destructive"` "Borrar facturas". The action handler calls `preventDefault()` so the dialog stays open while it runs. Pending: both buttons disabled, the action reads "Borrando…" with a spinning `LoaderCircle`, Escape and overlay clicks do nothing. Success: the dialog closes, sonner toast "Facturas borradas de este navegador", and the page becomes the guided empty state (all tabs do the same via the store's cross-tab notification). Failure: the dialog stays open with an `Alert variant="destructive"` inside it (title "No se pudieron borrar las facturas", body "Intenta de nuevo.") and the action returns to "Borrar facturas". Focus returns to the trigger on cancel. Delete does not sign the user out.

### Sign-out and other-account paths (D-24)
"Cerrar sesión" (header) and "Usar otra cuenta" (`/acceso-denegado`) wipe the browser data first, then sign out. While running the pressed button is disabled and reads "Cerrando sesión…" / "Cambiando de cuenta…" with a spinning `LoaderCircle`. If the wipe times out, sign-out continues (the owner gate and the server header cover it, RESEARCH Finding 7). If sign-out itself fails, the user stays on the page, the button returns to normal and a sonner error toast reads "No se pudo cerrar la sesión. Intenta de nuevo." (the one allowed error toast: the header has no inline slot). If the browser held invoices of a different account, they are deleted before any data renders; this happens silently, with no extra UI.

**Keyboard and focus**: all controls are native or Radix, so Tab order follows DOM order and every control shows the preset focus ring (`focus-visible:ring-3`). The picker is opened by Enter/Space on a real `<button>`. Table row links, the brand link and the back link are real `<a>` elements. Escape closes the Select and the `AlertDialog` (except while a delete is pending); the dialog traps focus and returns it to the trigger; the `<details>` toggles with Enter/Space. The drop zone has no role and is not focusable.

**Motion**: no custom animation. Charts are static (`isAnimationActive={false}`); the only motion is the spinner, the `Progress` width transition and the 100 ms fade/zoom of the shadcn `AlertDialog` (the preset's own, accepted).

**Hover / click affordances**: bars in the top-10 chart show `cursor-pointer` and the `--chart-2` fill; table rows highlight on hover; nothing else is clickable without an underline, border or button chrome.
